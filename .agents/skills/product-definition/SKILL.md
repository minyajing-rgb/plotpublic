# Product definition
Read actual repo/app/current owner decisions. READ full PRD and flows/architecture; render and INSPECT actual visual references, not filenames or code. Preserve independent product identities and approved design.
Write PRD, every concrete page/feature/state/branch matrix with IDs, per-screen UI specs and actual reference/approval, complete happy/error/empty/loading/permission/cancel/back/refresh flows, component/data/API/auth/privacy/release architecture, builder work order and requirement→page→flow→test traceability. Include responsive and full language content. Never silently shrink to a homepage.
Put the whole pack INSIDE the actual builder environment, verify receipt/result, respect exact prompt contract and one writer per app. A send receipt is not completion. Preserve existing production/data/permissions; reuse recovery points instead of more backup projects. No unauthorized publishing, billing/domain/auth/data changes, or fabricated artwork, results, model calls, successful submissions or metrics.
Then automatically execute product-acceptance: independently inspect, fix and retest before owner review. Missing reference/service/evidence is BLOCKED, not complete. Backend-only exclusions need explicit reason.
